# BARIBAL — сайт студии защитных технологий

**Обязательно перед любой работой:** прочитать [AGENTS.md](AGENTS.md). В нём зафиксирована обязательная проверка результата на опубликованном сайте; наличие файлов или успешного Actions не считается подтверждением.

Основной сайт BARIBAL — обычный статический HTML/CSS/JavaScript. Единственный рабочий источник страниц находится в `plain-site/`. GitHub Pages публикует его через workflow `.github/workflows/deploy-pages.yml`; сборка Vite не используется.

## Структура сайта

- `plain-site/` — главная страница, разделы сайта, каталог работ, стили и скрипты.
- `assets/` — общие локальные изображения и видео, используемые HTML-сайтом.
- `foto/` — дополнительные файлы для опубликованного сайта.
- `public/.htaccess` — настройка Apache для размещения на хостинге с поддержкой .htaccess.
- `maintenance/` — инструменты извлечения фотографий со старого Creatium-сайта, диагностики, нормализации и учёта ресурсов. Это служебные инструменты, они не являются частью сайта.

## Извлечение фотографий со старого сайта

Рабочие инструменты извлечения и проверки фотографий сохранены отдельно от сайта. Для карточек Creatium используйте GitHub Actions → **Extract and archive Creatium galleries**. Для карточек 8 и 9 сохранены отдельные workflow и скрипты загрузки/проверки оригиналов.

**Не менять алгоритм извлечения, селекторы, порядок кликов и настройки Playwright без отдельной необходимости и проверки.** Перед работой обязательно прочитать:
- [maintenance/README.md](maintenance/README.md)
- [maintenance/CREATIUM-EXTRACTOR-LOCK.md](maintenance/CREATIUM-EXTRACTOR-LOCK.md)

Playwright оставлен в зависимостях именно для этих служебных инструментов; он не используется для сборки или работы опубликованного сайта.

## Публикация

GitHub Actions копирует содержимое `plain-site/`, общие `assets/` и необходимые файлы из `foto/` в каталог публикации. Никакая Vite-сборка для сайта не нужна.
