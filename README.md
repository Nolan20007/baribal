# BARIBAL — сайт студии защитных технологий

**СНАЧАЛА ПРОЧИТАТЬ:** [00-START-HERE-DOMAIN-CUTOVER.md](00-START-HERE-DOMAIN-CUTOVER.md) — главная актуальная инструкция по финальному подключению домена к Timeweb. В ней зафиксированы текущий статус REG.RU, все DNS-записи, NS-серверы и порядок проверки сайта/почты. Не просить пользователя повторно диктовать DNS-данные.

**Обязательно перед любой работой:** прочитать [AGENTS.md](AGENTS.md). В нём зафиксирована обязательная проверка результата на опубликованном сайте; наличие файлов или успешного Actions не считается подтверждением.

Основной сайт BARIBAL — обычный статический HTML/CSS/JavaScript. Единственный рабочий источник страниц находится в `plain-site/`. GitHub Pages публикует его через workflow `.github/workflows/deploy-pages.yml`; сборка Vite не используется.

## Структура сайта

- `plain-site/` — главная страница, разделы сайта, каталог работ, стили и скрипты.
- `assets/` — единое хранилище общих изображений и видео сайта; новые постоянные изображения добавлять сюда в подходящую тематическую папку (`images/studio`, `images/services`, `images/pages` и т. п.).
- `foto/` — исходные портреты владельца и служебные файлы фото-формы; при публикации каталог копируется целиком, включая `foto1.png`–`foto3.png`.
- `plain-site/<раздел>/index.html` — отдельная папка каждого раздела; адрес страницы остаётся `/baribal/<раздел>/`.
- `public/.htaccess` — настройка Apache для размещения на хостинге с поддержкой .htaccess.
- `maintenance/` — инструменты извлечения фотографий со старого Creatium-сайта, диагностики, нормализации и учёта ресурсов. Это служебные инструменты, они не являются частью сайта.

## Извлечение фотографий со старого сайта

Рабочие инструменты извлечения и проверки фотографий сохранены отдельно от сайта. Для карточек Creatium используйте GitHub Actions → **Extract and archive Creatium galleries**. Для карточек 8 и 9 сохранены отдельные workflow и скрипты загрузки/проверки оригиналов.

**Не менять алгоритм извлечения, селекторы, порядок кликов и настройки Playwright без отдельной необходимости и проверки.** Перед работой обязательно прочитать:
- [maintenance/README.md](maintenance/README.md)
- [maintenance/CREATIUM-EXTRACTOR-LOCK.md](maintenance/CREATIUM-EXTRACTOR-LOCK.md)

Playwright оставлен в зависимостях именно для этих служебных инструментов; он не используется для сборки или работы опубликованного сайта.

## Публикация

GitHub Actions копирует содержимое `plain-site/` и общие `assets/` в каталог публикации. `maintenance/prepare-and-validate-site.py` автоматически нормализует пути к общим `assets/` и `foto/` для любой глубины вложенности, копирует весь каталог `foto/` и проверяет локальные ссылки, изображения, скрипты и таблицы стилей. Проверка не использует фиксированный список разделов: новые страницы `plain-site/<раздел>/index.html` автоматически попадают в публикацию и проверку. Ошибка в локальном пути останавливает публикацию. Никакая Vite-сборка для сайта не нужна.

## Общие формы обратной связи

Разметка двух форм хранится централизованно в `plain-site/components/contact-widget.html` и `plain-site/components/callback-modal.html`. При публикации `maintenance/build-shared-forms.py` автоматически удаляет старые встроенные копии, подключает актуальные общие формы к каждой HTML-странице в `plain-site/` и проверяет, что на каждой опубликованной странице присутствует ровно по одной форме каждого типа. Поэтому для новой HTML-страницы не нужно копировать разметку форм: достаточно разместить страницу внутри `plain-site/`; общие формы будут добавлены при следующей публикации. Кнопки записи открывают центральную форму через класс `.js-callback`. Плавающая форма подключается автоматически.
