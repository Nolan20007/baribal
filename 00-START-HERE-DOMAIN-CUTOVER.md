# BARIBAL — финальная инструкция подключения основного домена к Timeweb

> **Главный документ для продолжения работ.** Если работа продолжается после перерыва, сначала читать эту инструкцию. Здесь зафиксировано текущее состояние на 23 ноября 2026 года, DNS-записи, уже выполненные действия и точный порядок проверок. Пользователя не нужно просить повторно диктовать DNS-значения.

## 1. Цель

Подключить основной домен `baribal-studio.ru` к новому сайту BARIBAL на Timeweb, сохранить работу почты и проверить формы/админку. Старый сайт Creatium не удалять, пока новый сайт и почта полностью не проверены.

Репозиторий: [Nolan20007/baribal](https://github.com/Nolan20007/baribal)  
Рабочая ветка: `main`. Ветку `test-project` не трогать.  
Новый сайт: обычные HTML/CSS/JS в `plain-site/`; Vite/White/Vital не использовать.

## 5. Что проверить следующим рабочим сеансом — строго по порядку

### Шаг 1. Проверить публичную DNS-делегацию

- Проверить NS для `baribal-studio.ru` через независимый DNS lookup (например, DNSChecker или dig/Whois DNS lookup).
- Ожидаемые NS — четыре сервера Timeweb из раздела 4.
- Если часть проверок ещё показывает Creatium, это может быть распространение/кэширование. Не менять настройки повторно и не нажимать сохранение снова без причины.
- Проверить A, AAAA, MX, TXT и CNAME уже после того, как авторитетная делегация указывает на Timeweb.
- Убедиться, что `www.baribal-studio.ru` разрешается через CNAME в корневой домен.
- Не использовать факт открытия старого сайта в одном браузере как единственное доказательство: браузер/провайдер может кэшировать старый DNS или страницу.

### Шаг 2. Проверить DNS-зону в панели Timeweb

Сверить с таблицей раздела 3. Пользователь уже вводил все восемь записей; не заставлять его читать их повторно. Если нужен скриншот, попросить один-два скриншота всего списка, а не переписывать значения вручную.

Особенно проверить:
- A совпадает с IP, назначенным именно сайту/хостингу Timeweb;
- AAAA совпадает с актуальным IPv6 Timeweb;
- MX и приоритеты 10/20 не затронуты;
- SPF, DKIM и DMARC присутствуют;
- CNAME `www` → `baribal-studio.ru`.

Не менять MX/TXT ради запуска сайта. Если запись требует коррекции, сначала установить точную причину и проверить актуальную инструкцию Timeweb.

### Шаг 3. Убедиться, что новый сайт действительно размещён в правильном каталоге

- В панели Timeweb открыть управление сайтом/доменом и проверить, к какой папке привязан `baribal-studio.ru`.
- Проверить, что в каталоге лежит актуальная production-версия нового plain HTML сайта, а не пустая папка и не старый/тестовый сайт.
- В проекте ручной Timeweb workflow: [Deploy BARIBAL to Timeweb](https://github.com/Nolan20007/baribal/actions/workflows/deploy-timeweb.yml).
- Timeweb deploy запускается вручную через GitHub → Actions → Deploy BARIBAL to Timeweb → Run workflow → ветка `main`. Обычный push сам по себе Timeweb не обновляет.
- Workflow выкладывает публичный сайт в `./baribal/public_html/`, а приватные файлы — отдельно вне публичного каталога. Проверить соответствие фактического каталога привязке домена.
- Не считать успешный Actions доказательством того, что домен открывает новый сайт. Проверить сайт в браузере после обновления DNS.

### Шаг 4. SSL и адреса сайта

После того как домен реально разрешается на Timeweb:
- Выпустить/включить бесплатный Let's Encrypt SSL для `baribal-studio.ru` и `www.baribal-studio.ru` (если оба имени используются).
- Проверить открытие `https://baribal-studio.ru` и `https://www.baribal-studio.ru`.
- Проверить редирект HTTP → HTTPS и выбрать единый канонический вариант с www или без www, чтобы не было циклов.
- Проверить главную, внутренние страницы, изображения, CSS/JS, мобильную версию и отсутствие смешанного HTTP-контента.

### Шаг 5. Проверить заявки и админку

- Отправить тестовую заявку через опубликованный сайт.
- Убедиться, что заявка появилась в админке и имеет корректный номер/данные.
- Проверить работу API, статусов и накопительных заявок.
- Не считать форму работающей только потому, что она показывает сообщение об успешной отправке: запись должна реально появиться в админке.

### Шаг 6. Проверить почту отдельно

Почтовые адреса:
- `info@baribal-studio.ru` — основной адрес получения клиентских обращений.
- `zayavki@baribal-studio.ru` — SMTP-отправитель уведомлений сайта.

Провести реальные тесты:
1. Отправить внешнее письмо с другого почтового сервиса на `info@baribal-studio.ru`.
2. Отправить письмо из `zayavki@` на `info@`.
3. Отправить заявку с сайта и проверить письмо-уведомление на `info@`.
4. Проверить папки «Спам» и «Все письма», а при ошибке — bounce/журнал доставки.
5. Проверить SPF/DKIM/DMARC по публичным DNS-записям.

**Историческая проблема:** раньше письма на `info@` не приходили даже при внутреннем тесте и внешнем письме. Поэтому входящую почту нельзя считать рабочей, пока не пройдёт новый внешний тест после переключения DNS.

### Шаг 7. Финальное подтверждение

Считать подключение завершённым только когда:
- публичные NS указывают на Timeweb;
- A/AAAA/CNAME разрешаются правильно;
- корневой домен и www открывают новый сайт;
- HTTPS работает без ошибок;
- тестовая заявка сохраняется в админке;
- письмо с уведомлением приходит на `info@`;
- внешнее письмо на `info@` действительно доставляется.

## 6. Что нельзя делать до успешной проверки

- Не удалять сайт Creatium и не отключать его аккаунт.
- Не удалять временный домен Timeweb `co376877.tw1.ru`, пока он нужен для тестов.
- Не удалять почтовые ящики.
- Не менять MX, SPF, DKIM, DMARC или AAAA наугад.
- Не переносить сам домен из REG.RU к другому регистратору в рамках этой операции: сейчас выполнена только смена NS.
- Не считать 24 часа гарантированным сроком: распространение может занять больше времени в отдельных DNS-кэшах.
- Не публиковать пароли, токены, SMTP-данные и GitHub Secrets в репозитории или чате.

## 7. После запуска домена

Когда домен, SSL, формы и почта подтверждены:
1. Проверить GA4 (ранее замечен ID `G-33M762M7CX`) и Яндекс Метрику.
2. Проверить `robots.txt`, `sitemap.xml`, canonical и редиректы.
3. Подключить/проверить Google Search Console и Яндекс Вебмастер, отправить sitemap.
4. Настроить Crontab ежедневного отчёта по инструкции [TIMEWEB-DAILY-REPORT.md](TIMEWEB-DAILY-REPORT.md) — только после подтверждения почты.
5. Затем проверить политику конфиденциальности, реквизиты и резервное копирование.
