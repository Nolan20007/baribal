# BARIBAL — отложенная задача: мониторинг рейтингов

**Статус: НЕ РЕАЛИЗОВЫВАТЬ СЕЙЧАС.** Не добавлять вкладки, блоки, виджеты, таблицы БД, сбор данных или другие функции рейтингов на публичный сайт и в админку. Не включать их в обычный деплой. Вернуться к задаче отдельно, когда появится время получить необходимые данные и доступы.

## Что нужно будет сделать позже

Подключить мониторинг карточки BARIBAL в трёх сервисах: Google Maps, Яндекс Карты и 2ГИС. Для каждой площадки выяснить и получить разрешённый официальный способ доступа к рейтингу и количеству отзывов. Затем отдельно согласовать, нужен ли только показ текущих значений или также ежедневная история изменений.

- **Google Maps:** получить Place ID карточки BARIBAL и настроить Google Places API (New) с API-ключом. Проверить актуальные условия и стоимость запрашиваемых полей. Документация: https://developers.google.com/maps/documentation/places/web-service/place-details
- **Яндекс Карты:** выяснить, какой официальный API или иной разрешённый способ позволяет получать рейтинг и количество отзывов на сервере. Не считать виджет полноценным API для собственной истории. Документация: https://yandex.ru/support/business-priority/ru/reviews/rating
- **2ГИС:** получить код официального виджета из кабинета BARIBAL и отдельно выяснить у 2ГИС, доступен ли официальный API/экспорт для серверного получения рейтинга и количества отзывов. Публичный API может не предоставлять рейтинг компании. Документы: https://dostavili.2gis.ru/public/0424/biz/ и https://help.2gis.ru/question/otkuda-beryotsya-reyting-kompaniy

## Что уже известно, только для ориентира

При ручной проверке пользователь сообщил для 2ГИС: **4,4 и 39 отзывов**. Это не подключённые данные и не команда показывать их на сайте. Перед будущей реализацией значения нужно перепроверить.

## Требования к будущей реализации

1. Использовать только официальные API, виджеты или согласованные способы доступа. Не парсить HTML, не запускать браузерную автоматизацию и не обходить ограничения площадок.
2. Секретные ключи хранить только в приватной конфигурации Timeweb или защищённых секретах GitHub Actions; никогда не коммитить их в публичный репозиторий.
3. До начала разработки согласовать, какие данные показывать публично, какие — только в админке, и как часто обновлять.
4. Если будет нужна история, сохранять только реально полученные снимки с датой, источником и статусом проверки. Не создавать фиктивные значения или историю.
5. Реализовывать отдельным согласованным этапом. До этого не менять публичный сайт, админку, базу данных и рабочий процесс деплоя ради рейтингов.
