# Инструкция: как качественно извлекать фотографии из Creatium

**Сначала прочитать эту инструкцию перед любой новой работой с фотографиями каталога.** Она сохраняет проверенную процедуру, найденную в истории GitHub при получении 14 оригиналов для карточек 8 и 9 (18 ноября 2026).

## Коротко: правильная последовательность

1. Получить прямые URL фотографий из галерей нужных карточек с помощью диагностического скрипта.
2. Проверить журнал: ссылки должны относиться к активной галерее нужной карточки, а изображения должны загружаться в полном размере.
3. Вручную сверить набор фотографий и соответствие проекту.
4. Передать подтверждённые URL отдельному скрипту скачивания/подготовки.
5. Проверить скачанные файлы, затем подключить их к карточкам и опубликовать.

**Не пропускать проверку между этапами 1 и 4.** Не привязывать фотографии к каталогу только потому, что workflow завершился со статусом Success.

## Эталонный пример в GitHub

- Публикация карточек 8–9: [Actions run 44274117601](https://github.com/Nolan20007/baribal/actions/runs/44274117601).
- Диагностический скрипт: `maintenance/tools/diagnose-creatium-originals.mjs`.
- Скрипт скачивания тестовых оригиналов: `maintenance/tools/download-creatium-cards-8-9.mjs`.
- Скрипт подготовки оригиналов: `maintenance/tools/prepare-creatium-cards-8-9.mjs`.
- Применение подготовленных карточек: `maintenance/tools/apply-creatium-cards-8-9.mjs`.

## Этап 1. Получить прямые адреса оригиналов

В GitHub открой **Actions → Diagnose originals using proven Creatium extractor → Run workflow**:

[Открыть workflow диагностики](https://github.com/Nolan20007/baribal/actions/workflows/diagnose-creatium-originals.yml)

Заполнить параметры:

- **First card to process** — номер первой карточки.
- **Last card to process** — номер последней карточки. Для одной карточки указать тот же номер.
- **Maximum additional gallery photos per card** — `0`, чтобы взять все фотографии.
- **Optional text check** — желательно указать уникальный текст/название проекта из карточки как дополнительную защиту от ошибки выбора.
- **Source page URL** — `https://baribal-studio.ru/foto`.

Запустить workflow и открыть журнал шага **Inspect originals using proven gallery-click logic**.

### Как работает проверка

Скрипт `diagnose-creatium-originals.mjs`:

- открывает старую страницу Creatium в Chromium;
- выбирает карточки по порядку и открывает галерею «Все фото»;
- ищет ссылки `a.fancybox[href]` только внутри активного окна `.modal0-root.is-active`, а не во всей странице;
- получает прямые CDN URL из ссылок галереи;
- загружает каждое изображение в браузере и проверяет реальные `naturalWidth` / `naturalHeight`;
- принимает изображения размером не менее 500×300 px и пишет строки `ORIGINAL` с URL и размерами; неподходящие помечает `REJECTED`.

В контрольном запуске карточка 8 дала 9/9 оригиналов, карточка 9 — 5/5, все размером 1280×960. Это и есть проверенный способ добыть адреса. Не подменять его поиском картинок по всей странице, по обложкам или случайными CDN URL.

## Этап 2. Проверить результат до скачивания

В журнале для каждой карточки проверь:

- правильный номер и текст проекта;
- число ссылок в активной галерее;
- список строк `ORIGINAL` и реальные размеры;
- отсутствие подозрительных URL из другой карточки.

Скачай артефакт **creatium-originals-diagnostic** из этого запуска и изучи отчёт/файлы. Сопоставь фотографии с нужной работой вручную. Если галерея не та, число фотографий неожиданное или изображения не соответствуют проекту — остановиться, ничего не скачивать для публикации и не подключать к карточке.

## Этап 3. Скачать и подготовить подтверждённые оригиналы

Скрипты `download-creatium-cards-8-9.mjs` и `prepare-creatium-cards-8-9.mjs` содержат вручную прописанные адреса карточек 8 и 9. **Нельзя просто поменять в них номера карточек.**

Для новых карточек нужно взять подтверждённые URL из диагностического отчёта и адаптировать именно эту схему: явный список URL для каждой карточки, загрузка оригиналов с CDN, проверка HTTP-ответа, MIME-типа JPEG и размера файла (в эталонном prepare-скрипте — не менее 100 KB), отдельная обложка и галерея, метаданные карточки. Не угадывать URL и не использовать непроверенные результаты старых универсальных запусков.

После скачивания проверить сами файлы и визуально убедиться, что это те же изображения, которые были в диагностическом отчёте.

## Этап 4. Подключить и опубликовать

Только после проверки файлов адаптировать/использовать этап применения карточек по образцу `apply-creatium-cards-8-9.mjs`, обновить нужные записи каталога и выполнить публикацию через GitHub Pages. Проверить опубликованные карточки на сайте: обложку, порядок фотографий, открытие галереи и отсутствие битых ссылок.

## Запреты и предостережения

- **НЕ ИСПОЛЬЗОВАТЬ** универсальный `maintenance/tools/extract-creatium-images.mjs` и workflow **Extract and archive Creatium galleries**: этот метод признан ненадёжным.
- Не принимать результаты старых универсальных Playwright запусков за подтверждённые оригиналы.
- Не менять рабочие скрипты 8–9 без необходимости; они служат эталоном, но содержат адреса только своих карточек.
- Не привязывать фотографии к карточке до ручной проверки.
- Успешный статус GitHub Actions сам по себе не доказывает качество или правильное соответствие фотографий.
- Сначала испытать процесс на 1–2 карточках. После проверки качества можно масштабировать небольшими партиями.
