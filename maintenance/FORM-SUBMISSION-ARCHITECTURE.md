# Единая отправка заявок BARIBAL

## Текущее состояние

На сайте три пользовательских сценария, но один общий механизм отправки:

1. Центральная модалка обратного звонка — форма внутри #callback-modal.
2. Плавающий виджет связи — .contact-widget-form.
3. Форма расчёта стоимости на странице каталога — .estimate-form.

Сейчас все три формы работают только в тестовом режиме. На GitHub Pages endpoint намеренно пустой: реальные заявки с тестовой версии не отправляются. Посетитель видит честное сообщение, что приём заявок будет включён после установки обработчика на Timeweb.

## Как устроена схема

- Разметка двух общих форм по-прежнему хранится в plain-site/components/ и подключается сборкой maintenance/build-shared-forms.py.
- Все формы с классом .demo-form обслуживает один файл plain-site/js/lead-forms.js.
- Сборка добавляет на каждую страницу метатег baribal-lead-endpoint.
- Для GitHub Pages значение всегда пустое.
- Только workflow Timeweb может получить значение из переменной репозитория GitHub BARIBAL_LEAD_ENDPOINT. До готовности PHP-обработчика переменную не создавать или оставить пустой. После установки обработчика задать значение /api/lead.php.
- Относительный адрес /api/lead.php останется тем же после переключения с технического адреса Timeweb на baribal-studio.ru. HTML-формы и JavaScript переписывать не потребуется.

## Передача данных

Единый JSON-запрос передаёт:

- form_type: callback_modal, contact_widget или estimate;
- name, phone, car, service, selected_services;
- contact_methods — выбранные варианты: phone, max, telegram и/или other;
- contact_other — уточнение альтернативного способа связи;
- website — скрытое honeypot-поле для фильтрации простых ботов;
- page_url и page_title — страница, с которой отправлена заявка.

Ответ PHP-обработчика должен быть JSON с success: true только после успешной передачи уведомлений. При ошибке сервер возвращает HTTP-ошибку и success: false; интерфейс не показывает ложное подтверждение.

## Что установить на Timeweb

Веб-обработчик будет размещён по адресу /api/lead.php. Он должен:

1. Принимать только POST с JSON; корректно отвечать на OPTIONS, если это понадобится при тестировании.
2. Проверять метод, размер запроса, обязательный телефон, допустимые значения form_type и contact_methods.
3. Отклонять заполненное honeypot-поле, ограничивать частоту запросов и не доверять данным браузера.
4. Отправлять уведомление на согласованный e-mail через SMTP и в Telegram через Bot API.
5. Хранить SMTP-пароль, адрес получателя, токен бота и chat ID только в закрытой конфигурации на Timeweb — не в HTML, JavaScript, GitHub Actions log или публичном репозитории.
6. Не сохранять лишние персональные данные и не выводить их в технические логи.
7. Возвращать success: true только после подтверждённой передачи уведомлений.

Рекомендуемые параметры закрытой серверной конфигурации: SMTP host, port, username, password, адрес получателя, Telegram bot token и Telegram chat ID. Секреты нельзя просить вставлять в этот файл или коммитить в GitHub.

## Порядок включения

1. Завершить юридическую проверку: текст согласия на обработку персональных данных, ссылка на актуальную политику и подтверждённые сведения об операторе должны быть доступны до отправки формы.
2. Разместить PHP-обработчик и закрытую конфигурацию на Timeweb.
3. Проверить SMTP и Telegram отдельной тестовой заявкой на техническом адресе Timeweb.
4. После успешной проверки задать GitHub Actions variable BARIBAL_LEAD_ENDPOINT со значением /api/lead.php и выполнить Timeweb deploy.
5. Проверить все три сценария: callback, плавающий виджет и расчёт стоимости; отдельно проверить ошибку сервера, повторную отправку и защиту от двойного нажатия.
6. При переключении домена относительный API-адрес останется прежним. Повторно проверить доставку уже на постоянном домене.

Важно: не задавать BARIBAL_LEAD_ENDPOINT для GitHub Pages и не включать реальную отправку до размещения и проверки обработчика на Timeweb.
