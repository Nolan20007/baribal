# BARIBAL — план завершения сайта

Рабочий план для следующих сессий. Обновлять статусы и результаты по мере выполнения.

## Правила работы
- Рабочая версия: plain HTML + JavaScript в `plain-site/`; публикуемый сайт — GitHub Pages.
- Основная ветка: `main`. Не трогать постороннюю ветку `test-project`.
- Заброшенную Vite/White/Vital-версию не возвращать в рабочий процесс.
- Проверять именно опубликованный сайт: https://nolan20007.github.io/baribal/ — исходники и локальная сборка сами по себе не доказывают, что исправление работает.
- Не менять дизайн и поведение без необходимости; перед рискованными изменениями выяснять сомнения.
- После каждой партии изменений запускать GitHub Actions, проверять успешную публикацию и затем проверять опубликованный результат.
- Не удалять фотографии, скрипты извлечения, данные галереи и общие компоненты, пока не проверено, где они используются.
- Отвечать пользователю коротко и по делу; сообщать конкретный результат и ссылку на Actions.

## План работ

### 1. Контрольный аудит опубликованного сайта — В РАБОТЕ
Проверить опубликованную версию на мобильном и desktop:
- главная: блоки, карточки работ, переходы, кнопки, шапка/подвал;

- все основные CTA и ссылки, включая телефонные и внешние;
- все модальные окна и формы: открытие, закрытие, прокрутка, высота, корректность контекста услуги;
- мобильная и широкая раскладка, переполнения, изображения и ошибки загрузки;
- раздел «Наши работы»: карточки, фотографии, переходы и доступность всех заявленных работ;
- проверить остаточные упоминания/URL удалённой услуги.
Фиксировать найденные дефекты; исправлять безопасные и однозначные, после чего повторно проверять опубликованную страницу. Не считать проверку полной, если фактически не проверены соответствующие состояния/устройства.

### 3. Подготовка и перенос на Timeweb
- Собрать чистую финальную HTML-версию из проверенной сборки `dist`.
- Проверить содержимое ZIP: только необходимые файлы сайта, без заброшенного Vite-проекта и служебного мусора.
- Пользователь загружает ZIP через файловый менеджер Timeweb в `public_html`.
- До отдельного согласования не менять DNS/NS и не переключать домен `baribal-studio.ru`, который находится у Recru.
- После загрузки проверить сайт на временном адресе, затем согласовать подключение домена, DNS и SSL.
- GitHub Pages оставить контрольной опубликованной копией до завершения проверки.

- PageSpeed исправлять только безопасно, без ухудшения дизайна, функциональности и аналитики.
